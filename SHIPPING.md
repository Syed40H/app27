# Shipping Repa

Expo Go is a development tool only. Release builds go through EAS Build (which
produces the `.ipa`) and EAS Submit (which uploads it). Both work on Windows —
no Mac needed.

## Before the first build

1. **Reserve the name** in App Store Connect early: `Repa - Gym Workout Tracker`.
   The `Rep-` prefix is crowded, and there is some chance Apple flags it as
   confusingly similar to the existing "Rep - Workout Tracker". Find that out
   now, not after the app is finished.

2. **Set the bundle identifier.** `app.json` currently has
   `com.hadisyed.repa` — change it if you want a different one, but change it
   *before* the first build, because it cannot be changed afterwards.

3. **Create the EAS project** and paste the id into `app.json` at
   `expo.extra.eas.projectId`:

   ```bash
   npx eas-cli login
   npx eas-cli init
   ```

4. **Host a privacy policy** and put its URL in two places: the App Store
   Connect listing, and `PRIVACY_POLICY_URL` in
   `src/app/(tabs)/settings.tsx` (currently a placeholder). GitHub Pages,
   Netlify or Vercel are all fine and free. `PRIVACY.md` in this repo is a
   starting draft.

5. **Replace the app icon.** `assets/images/icon.png` is generated by
   `scripts/generate-icons.js` — a bold monogram R in the accent colour on the
   paper background. It is real, valid art (1024x1024, opaque, square corners),
   but a designed icon will do better on the store.

## Builds

```bash
npx eas-cli build --profile production --platform ios
npx eas-cli submit --platform ios
```

The free tier allows 15 iOS builds a month with a 45-minute timeout — plenty.

For screenshots and the review video, use the demo profile, which bakes in
sample workouts so no screen is ever empty:

```bash
npx eas-cli build --profile demo --platform ios
```

**Never submit the `demo` build to the App Store.** Sample workouts must not
reach real users.

## App Store Connect

- **Privacy nutrition label: Data Not Collected.** This is the honest answer —
  there is no backend, no analytics, and no network calls of any kind.
- **Camera usage string** is already set in `app.json`: *"Used to add photos of
  your gym equipment to custom exercises."* Camera is the only permission.
- **Export compliance:** `ITSAppUsesNonExemptEncryption` is already `false` in
  `app.json`, so the question is pre-answered.
- **Age rating** and a **Support URL** are still needed.
- **Screenshots must match actual app behaviour** — mismatches get rejected
  under Guideline 2.3.

## Guideline 4.2, the main rejection risk

Apple rejects apps that do not *appear* finished, and a reviewer's first-run
test lasts 30–90 seconds. An empty logger is exactly that profile.

The spec's rule is that sample data must never reach real users, and only one
binary gets submitted — so the reviewer's build is the production build, and it
will start empty. Mitigate it this way:

1. **Record a short demo video** from the `demo` build and put it in App Review
   Notes. This is the primary mitigation.
2. In the review notes, say plainly what the app does that competitors do not:
   it shows where in the previous session each exercise fell, so you know
   whether last time's numbers came from being fresh or fatigued.
3. Offline-first, on-device storage already counts as a native advantage.
4. If 4.2 still comes back, the Home Screen widget is the strongest remaining
   signal — it was deliberately deferred to v1.1 because it needs a separate
   target and app group, which complicates EAS builds.

## Listing copy

Name, subtitle and keywords are 30 / 30 / 100 characters, and repeating a word
across them wastes budget — the algorithm indexes all three together.

- **Name:** `Repa - Gym Workout Tracker` (26)
- **Subtitle:** put the fatigue-context angle here, since no competitor can
  claim it. For example: `See your last lift and when` (27)
- **Keywords:** avoid every word already used above — no "gym", "workout",
  "tracker", "lift". Reach for: `strength,reps,sets,log,barbell,dumbbell,routine,progress,fitness,training,pr`
